# Native agent GitHub tools

Reviewed 2026-10-24. Reference: `packages/gateway/src/tools/agent-github-tools.ts`.

The two native factories preserve status/instructions/test and short-lived-token presentation over an explicit typed asynchronous identity/service port. Their complete metadata preserves medium/high risks and once consent. The host retains owner checks, key protection, token expiry, and scoped/bounded GitHub transport. This adapter adds no AgentGithubAppService, network, credential storage or production activation credit.

`gateway_rust_agent_github_tools` runs the actual TypeScript factories with scripted service fixtures and compares output/errors plus every dependency call and argument. It covers unauthenticated refusal, optional current-agent lookup, explicit identity precedence, ECMAScript whitespace (including FEFF and non-whitespace U+0085), missing identities, initialization order, list/get/status counts, nullable and omitted fields, webhook-secret availability and the two distinct base-URL calls in instructions. Connection testing preserves nullish defaults and Error/non-Error stringification. Token checks cover absent/disconnected connections, empty/null last errors, unresolved environments, missing/empty/rich environment fields, expiry, complete environment retention, usage text, and error catch boundaries. Synthetic credentials are used throughout; no GitHub request is made.

Six isolated mutations target authentication, explicit-identity precedence, get ownership, connected-state enforcement, returned token mapping and thrown-value formatting. Evidence: `.jait/artifacts/gateway-rust/chat-loops/agent-github-expanded.log`, `agent-github-mutations.json` and `agent-github-mutations-restored.log`. The restored target has 10 checks, including four shared driver-boundary checks. JSON-compatible schema-valid tool inputs and typed service results are the supported port contract; direct malformed port values are not a substitute for host validation.
