# Native GitHub idle challenge cleanup review

Status: uncredited canonical service slice; frozen/restored validation passed. Production remains TypeScript.

The native host explicitly calls NativeGithubPort::start_expiry_cleanup and owns the returned GithubExpiryCleanup. Construction alone starts no task. The candidate binary does not mount this GitHub service, and no production timer has been activated. One runner per port is allowed; startup requires Tokio, a 1–60 second period, and a batch of 1–256. It runs an immediate initial sweep, then skips missed ticks rather than catching up. It shares the bounded database worker, skips a busy mailbox until the next tick, and returns fatal worker/storage errors through the join handle. is_finished lets runtime supervisors detect termination. A constant-size attempted_sweeps counter reports scheduling attempts, including busy/rejected ones, and does not imply successful updates. The current-thread queued-cancellation test waits for this admission point before cancelling. Runtime must close/cancel and await cleanup shutdown before database shutdown. Drop cancels the task; already-started SQLite work can finish.

Each indexed UPDATE clears at most the requested number of expired active rows in one atomic statement. Every callback phase, including uncertain and complete, is eligible at the exact deadline. Phase/revision/App/operation/reservation and public replay material are cleared; installed credentials and token cache are unaffected. Generation and last signed-state digest remain as tombstones: retaining the digest prevents reissuing the last nonce after expiry. Callback phase admission and late-result checks still use the canonical persisted authority. There is no per-owner in-memory cleanup map, second database worker, remote I/O or bypass of callback authorization.

Compatibility decision: this is a native-only extension outside the shared TypeScript schema ledger. The existing explicit native expire helper now caps its sweep at 256 rows and callers needing more use the recurring runner. The exact callback TTL remains unchanged. After a sweep, an expired row reports invalid/revoked authority instead of the unswept expiry diagnostic; both deny remote effects. The native host fixture exercises durable phase revocation; an actual HTTP callback after the maintenance tick is not yet exercised. Port close also signals cleanup cancellation. This scheduling policy intentionally differs from the TypeScript service, which has no corresponding durable authority cleanup; it grants no new external effect permission. Initial index creation and SQLite lock contention have no separately proven wall-time bound; the row-update bound is not a measured latency claim.

Focused lifecycle checks cover idle batching across seven phases, the canonical clock and exact expiry, tombstone/replay material behavior and credential preservation, invalid limits before schema creation, duplicate start and close, dropped handles, queued cancellation/drain, overload retry on the next tick, and visible SQL errors. The existing canonical expiry test now checks nonce reuse rejection and the next generation after cleanup. A stopped or failed runner cannot restart on the same port; hosts must rebuild the lifecycle explicitly.

Remaining service boundaries include state-bearing installation URL/browser issuance, external sink lifecycle/idempotency/fencing, token cache App binding/residency, direct credential ABA, cross-process callback ownership and host shutdown/deadlines. No service/component credit or full native gate is claimed. Platform, load/soak, recovery/rollback and activation gates remain open.

Validation provenance: the first cancellation control survived because its test had not established enqueue before cancellation. That run is discarded in discarded-control-evidence.json. Final controls must rerun against the corrected admission observation; compile errors do not count as caught controls. Earlier overlapping validator processes were stopped and discarded; the final validator owns a file lock and supervises its child process groups.
