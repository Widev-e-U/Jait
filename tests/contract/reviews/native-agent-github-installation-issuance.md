# Native GitHub installation URL issuance review

Status: uncredited canonical service slice; frozen/restored validation passed. Production remains TypeScript.

The native-only authenticated POST /api/agents/{agent}/github-app/installation-url issues an installation URL for the current configured App. HTTP authentication and the existing agent ownership resolver run before the port; the operation shares the canonical owner lease and global admission with callbacks, manual writes, tools and environment consumers. A short immediate SQLite transaction checks a numeric App ID, the decrypted key's presence and a bounded ASCII alphanumeric/hyphen slug, signs a new nonce, updates pending manifestState, and issues through the existing persisted challenge authority with current App/credential revision binding. Generation advancement and connection writes commit together. Invalid credentials/slug or a challenge-storage failure expose no successful URL and do not replace the prior challenge. URL path/host authority is fixed to https://github.com/apps/{encoded-slug}/installations/new and the query carries the newly issued state.

This response is an authorized issuance boundary: it constructs the URL from the fresh token and current App. Signed state is never added to challenge replay results. The existing connection row retains pending manifestState as it already does for setup; the challenge table keeps its digest. Successful installation clears pending state and persists only the allowlisted public connection for exact replay. This slice makes no claim to eliminate all persisted signed-state material, only its exclusion from replay blobs.

Compatibility decision: this is a native-only additive endpoint, with no TypeScript counterpart. It deliberately starts a fresh 15-minute absolute challenge and supersedes any previous URL/manifest challenge for that owner. Public callback restrictions and authenticated manual installation stay unchanged. Existing manifest conversion still redirects to the Agents page; it does not automatically redirect to GitHub or write state-bearing URLs into replay data. New actual HTTP contracts consume state extracted and checked from the issued URL through the native callback, not a fake TypeScript implementation of the endpoint. Existing TypeScript comparisons remain separate. No external GitHub website/browser was contacted. The present web frontend still constructs its original state-free link; frontend/typed API handoff to native issuance and actual browser behavior remain open. Production host composition is not enabled.

Eight new focused contracts cover a real HTTP callback after the explicit maintenance tick, fresh URL-to-callback installation and replay, new issuance superseding converted manifest state, authentication/ownership/missing App/key admission, unsafe slug rejection without generation rotation, expiry tick and manual replacement revocation, direct App/key changes before callback, and transaction rollback with continued usability of the prior URL. The existing held-owner contract now specifically rejects concurrent installation issuance. URL capture verifies HTTPS, GitHub host, and exact query state; callback replay inspection rejects any persisted installUrl or signed state in public replay blobs. Maintenance joins before the subsequent callback; expiry preserves the App and encrypted key. The native helper was factored from the existing actual-reference composition runner so native-only operations do not fabricate reference parity.
