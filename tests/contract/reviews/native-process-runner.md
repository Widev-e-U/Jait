# Native captured process runner

Reference: the actual private `runDockerProcess` and `runProcessWithInput` helpers in `packages/gateway/src/security/sandbox-manager.ts`. Native: `packages/gateway-rust/src/execution/process_runner.rs`. Target: `gateway_rust_process_runner`.

The lane-owned TypeScript driver extracts the complete function bodies from the source at explicit function boundaries and transpiles them with Bun; it injects only Node's real `spawn`. This avoids importing sandbox manager initialization, live host configuration, or invoking Docker. Fixtures execute local harmless processes with explicit arguments. There is no reimplementation of reference output/exit/timeout logic in the driver.

Focused comparisons cover standard output, standard error and nonzero exit status, empty output, ECMAScript BOM trimming, Unicode, stdin forwarding, literal shell metacharacters, and a process deadline retaining partial output. No fields are normalized. Spawn errors deliberately use typed native io::Error rather than exposing platform-dependent Node error text; invalid and missing executables are tested as failures with no tool or route registration.

Native safety extensions require a finite timeout (up to 24 hours), at most 16 MiB captured output and stdin, and bounded concurrent process admission without a waiting queue. Output retains a bounded UTF-8 byte tail while pipes continue draining; valid character boundaries and invalid-byte replacement both obey the cap. The request supplies cwd and the complete environment; host credentials are not inherited. Cancellation tokens are checked before effects and cancel running work. Unix children run in private process groups; timeout, cancellation, aborted futures, and owned group drop kill descendants in that group. Direct children are reaped before normal completion/cancellation releases admission permits. Native tests verify process and descendant termination, inherited-pipe deadlines, abort cleanup, capacity recovery, closed pool rejection, pre-cancellation, invalid argv, bounded output, and environment isolation.

Scope: Linux focused process execution, with no HTTP routes, tools, container access, assessment authorization, consent bypass, or live production tests. Callers must authorize the exact command, cwd, environment and execution node before invoking this primitive. This supports the sandbox/agent execution path but does not migrate or credit the whole sandbox manager. Process groups manage lifecycle and do not provide sandbox containment against deliberate daemonization/group escape; that requires a container/cgroup boundary. Windows process-tree cleanup and interactive PTYs remain separate work. Raw invalid UTF-8/chunk-boundary equivalence and platform-specific spawn error text are not claimed. Native output caps are an explicit bounded extension to the reference's unlimited capture.
